# 1c-check-task — открыть базу для проверки доработки

Открывает 1С:Предприятие на нужной форме, но **сначала проводит предварительный аудит**:
запуск базы дорогой, поэтому скилл не пускает в базу, пока не доказано, что проверять есть что
и проверка не будет пустой тратой времени.

Реализация: `scripts/check-task.py` (Python). Запуск клиента делегирован `db-run.py`,
глубокая проверка базы — `db-cfe-admin.py` (из того же набора скиллов).

## Предварительная проверка (preflight)

Выполняется по файлам и логам, без запуска 1С:

| Проверка | Что значит |
|---|---|
| Исходники | каталог существует, время последнего изменения |
| Загрузка | лог `db_load_xml_*` успешен и новее исходников |
| Свежесть загрузки | исходники не новее загрузки |
| Обновление БД | лог `db_update_*` успешен; блокировки (конфигуратор/фоновое задание) — FAIL |
| Свежесть обновления | обновление не старше загрузки |
| CFE | сборка новее исходников |
| Версия CFE | версия в имени CFE = `<Version>` в `Configuration.xml` |
| Чек-лист | есть и упоминает текущую версию |
| Цель URL | объект из URL есть в исходниках (Обработка/Справочник/Документ/Отчет/регистры) |
| Блокировка | конфигуратор этой базы не запущен |

Глубокая проверка (`-Deep`, вызов 1С, +10–20 с):

| Проверка | Что значит |
|---|---|
| Применимость | `db-cfe-admin check apply` — расширения применимы к конфигурации |
| Версия в базе | применённая в базе версия расширения = `<Version>` в `Configuration.xml` |

`FAIL` — запуск отменяется (код возврата 2). `WARN` — запускаем, но предупреждаем.
Обход: `-Force`. Только аудит: `-PreflightOnly`. Пропустить: `-SkipPreflight`.
Машиночитаемый вывод: `-Json`.

## Конфигурация проекта (универсально)

Скилл читает `.v8-project.json` в корне проекта. Для аудита используется секция `check`:

```json
"check": {
  "database": "test6",
  "url": "e1cib/app/Обработка.МояОбработка",
  "checklist": "checks/current.md",
  "build": {
    "srcDir": "src/cfe/МоёРасширение",
    "configXml": "src/cfe/МоёРасширение/Configuration.xml",
    "cfePattern": "МоёРасширение_*.cfe"
  }
}
```

Без секции `check`: `srcDir` — из `databases[].extensions[].src`, `Configuration.xml` —
внутри `srcDir`, CFE — `*.cfe` в корне, чек-лист — `checks/current.md`, URL — из аргумента.

## Как определить базу и URL из контекста

**База** (по убыванию приоритета): 1) указанная пользователем; 2) база, в которую в этой
сессии загружались исходники/CFE (`db-load-xml`, `db-update`, `db-cfe-admin`); 3) `default`
из `.v8-project.json`. Учётные данные (`user`, `password`, `server`, `ref`) — из записи базы.

**URL** (по убыванию): 1) указанный пользователем; 2) `check.url`; 3) если менялась конкретная
форма — `e1cib/app/Обработка.<Имя>`, `e1cib/data/Справочник.<Имя>` / `Документ.<Имя>`;
4) открыть базу без URL.

**Чек-лист**: `checks/current.md` (или `check.checklist`) — файл откроется рядом.

## Команда

```bash
python "C:\Users\Grishin1c\.config\opencode\skills\1c-check-task\scripts\check-task.py" -Database "test6" -Url "e1cib/app/Обработка.АРМОД_ОчередиОбработкиДокументов" -Checklist "E:\Grishin\Code\APM\checks\current.md" -Deep
```

### Параметры

| Параметр | Обязательный | Описание |
|----------|:------------:|----------|
| `-Database <id>` | нет | id / alias / ref / имя базы; по умолчанию `default` |
| `-Url <e1cib/...>` | нет | навигационная ссылка, открываемая при старте |
| `-CParam <строка>` | нет | параметр запуска `/C` |
| `-Checklist <файл>` | нет | файл с описанием шагов проверки |
| `-ProjectDir <путь>` | нет | каталог проекта (поиск `.v8-project.json` вверх) |
| `-PrintOnly` | нет | только показать команду, не запускать |
| `-PreflightOnly` | нет | выполнить только аудит, базу не открывать |
| `-SkipPreflight` | нет | пропустить аудит (не рекомендуется) |
| `-Force` | нет | запустить несмотря на `FAIL` (осознанно) |
| `-Deep` | нет | проверка применимости и версии расширения в базе |
| `-Json` | нет | вывод результата в JSON |

## Порядок работы

1. Определи базу и URL по правилам выше (из контекста задачи, не спрашивай без нужды).
2. Вызови скрипт (для проверки применимости/версии — с `-Deep`).
3. Сообщи одной строкой: база, URL, PID, где чек-лист.
4. Если человек прислал ошибку — правки, сборка CFE, снова этот скилл.

## Важно

- Скилл **запускает клиент**, но не проверяет UI: агент не видит окно 1С. Результат — от человека
  или из файла, который пишет сама обработка (например, `checks/last-result.json`).
- Пароль берётся из `.v8-project.json`; в отчётах его не выводить.
- Если `-Deep` показал «Версия в базе» = FAIL — обновите приложение (`db-update`) или
  перезапустите клиент: изменения не применены.

## Запуск в DSH — без ожидания оболочки

Долгий вызов запускай через `pwsh` с `run_in_background: true` и `CC_SYNC=1`:

```powershell
$env:CC_SYNC='1'; python "$env:USERPROFILE\.dsh\skills\<скилл>\scripts\<скилл>.py" <аргументы>
```

DSH сразу вернёт job id (аналог `RUN_ID`), по завершении пришлёт уведомление.
`job_output` — хвост лога и результат, `job_list` — статус, `job_kill` — остановка.
Ждать синхронно не нужно.

Команда без `CC_SYNC=1` сама уходит в фон через `async_run.py` и печатает `RUN_ID` —
этот путь оставлен для совместимости с opencode и общим монитором:
`python "$env:USERPROFILE\.dsh\skills\_shared\async_run.py" status <RUN_ID>` (также `start`, `tail`, `list`, `wait`).
Данные — `%LOCALAPPDATA%\cc_async`, тот же формат, что у opencode.
Монитор для человека: `python "$env:USERPROFILE\.dsh\skills\_shared\cc-status.py"`.
Полный протокол — `E:\Grishin\Code\_store\PROCESS.md`.
