# /1c-init — инициализация проекта или расширения

Единая точка старта: читает настройки `_store` и выбирает **свободную** тестовую базу.
Сначала выбери ветку по запросу пользователя:

- пустая папка, подготовить окружение, имя расширения ещё не выбрано → `-ProjectOnly`;
- сразу создать проект и заготовку CFE → `-Name <имя>`;
- подключить существующий проект с `.v8-project.json` к стору → `-Adopt`.

Для `-ProjectOnly` не спрашивай имя расширения: этот режим специально позволяет отложить его выбор.

## Что делает

1. Читает реестр `_store\.v8-project.json` (v8path, базы test1…test7).
2. Выбирает базу: `-Database` либо первую **свободную** (не занята конфигуратором
   и активным async-заданием; приоритет — `default` из стора).
3. Создаёт `<проект>\.v8-project.json`: все базы стора + `default` = выбранная +
   секция `check` (пути сборки, чек-лист).
4. Заготовка расширения в `src\cfe\<Имя>`:
   - если в `_store\reference\extensions\<Имя>\*` есть эталон — копирует его (последняя версия);
   - иначе — `cfe-init` (Purpose=AddOn, префикс, `-ConfigPath` из эталона).
5. Готовит `build\`, `checks\current.md`.

В режиме `-ProjectOnly` создаются `.v8-project.json`, `build\`, `checks\current.md`
и `AGENTS.md` с правилами проекта (если файла ещё нет — существующий не перезаписывается).
исходники расширений не создаются и не изменяются. `check.url` остаётся пустым до определения задачи.

## Команда

```bash
# Только подготовить пустой проект; имя расширения можно выбрать позже.
python "C:\Users\Grishin1c\.config\opencode\skills\1c-init\scripts\1c-init.py" ^
  -ProjectDir "E:\Grishin\Code\НовыйПроект" -ProjectOnly

# Создать расширение сразу.
python "C:\Users\Grishin1c\.config\opencode\skills\1c-init\scripts\1c-init.py" ^
  -ProjectDir "E:\Grishin\Code\НовыйПроект" -Name "БКК_НовоеРасширение" -NamePrefix "бкк_"
```

### Параметры

| Параметр | Обязательный | Описание |
|----------|:------------:|----------|
| `-ProjectDir <путь>` | да | папка проекта |
| `-Name <Имя>` | условно | имя расширения (= имя объекта метаданных); нужно для создания CFE-заготовки |
| `-ProjectOnly` | нет | подготовить проектную среду без расширения; выбрать имя можно позже |
| `-Adopt` | нет | подключить существующий проект к стору (без `-Name`): добавить базы/`v8path`/`check.database`, ничего не создавая |
| `-Synonym <строка>` | нет | синоним |
| `-NamePrefix <префикс>` | нет | префикс имён (по умолчанию из стора, иначе `бкк_`) |
| `-Version <X.Y.Z>` | нет | начальная версия (по умолчанию `1.0.0`) |
| `-Database <ref>` | нет | принудительно выбрать базу |
| `-StoreDir <путь>` | нет | стора (по умолчанию `E:\Grishin\Code\_store`) |
| `-NoScaffold` | нет | не создавать заготовку расширения |
| `-DryRun` | нет | только показать план, ничего не создавать |
| `-Force` | нет | дополнить существующий `.v8-project.json` с резервной копией / разрешить занятую базу |

### Добавить расширение позже

После `-ProjectOnly` расширение можно создать в той же папке командой:

```bash
python "C:\Users\Grishin1c\.config\opencode\skills\1c-init\scripts\1c-init.py" ^
  -ProjectDir "E:\Grishin\Code\НовыйПроект" -Name "БКК_НовоеРасширение" -Force
```

Существующие настройки проекта будут дополнены; скрипт создаст заготовку расширения и build-настройки.

## Что дальше

1. Правки XML в `src\cfe\<Имя>` (эталоны — в `_store\reference`).
2. Сборка CFE → `build\` (навыки cfe-*).
3. Проверка: `1c-check-task` (preflight + запуск выбранной базы).

## Важно

- Исходники расширений — только в проекте; `_store` не меняется (кроме шага
  публикации сборок по правилам стора).
- Типовая конфигурация не редактируется — все доработки в расширениях.

## Запуск через MCP (`cc`) — без ожидания оболочки

Долгий вызов этого скилла запускать инструментом MCP-сервера `cc`:
`run_start(script="<имя>.py", args=[...])` → `run_id`; затем жди через
`run_wait(run_id, timeout_sec=60)` (для долгих операций — до 600 секунд). Если ожидание
истекло, а задача ещё выполняется, повтори `run_wait`. `run_tail` читай после завершения
или для диагностики; `run_status` используй только для разовой проверки состояния.

Fallback без MCP: `python "C:\Users\Grishin1c\.config\opencode\skills\_shared\async_run.py" start -- python "<этот-скрипт>" <аргументы>`.
Мониторинг: `python "C:\Users\Grishin1c\.config\opencode\skills\_shared\cc-status.py"`.
Полный протокол — `E:\Grishin\Code\_store\PROCESS.md`.
