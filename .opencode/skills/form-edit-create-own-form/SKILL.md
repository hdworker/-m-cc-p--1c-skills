# Создание собственной формы

Применяй для новой формы, не для изменения формы поставщика. Сначала определи, где будет жить форма: в объекте конфигурации, в CFE, в общей форме, во внешней обработке (EPF) или внешнем отчёте (ERF). Сам факт «форма новая» не означает, что нужно создавать новый объект метаданных.

## Маршрут

1. **Новый объект конфигурации** — создай объект через `/meta-compile`; проверь, создалась ли уже форма. Если формы нет — добавь её через `/form-add`; опиши или заполни структуру через `/form-compile`.
2. **Форма к существующему объекту** — `/form-add`, затем `/form-compile` для элементов, реквизитов, команд и событий.
3. **Внешняя обработка/отчёт** — начни со scaffold `/epf-init` или `/erf-init`; добавь управляемую форму через `/form-add` и опиши её `/form-compile`, если форма нужна артефакту.
4. **Форма в расширении** — для нового CFE используй `/cfe-init`, затем создай собственный объект/общую форму подходящим `/meta-compile` и построй её форму. Для изменения существующего типового объекта сначала выбери механизм через `/1c-extension-strategy`; изменение типовой формы и её заимствование — ветка `/form-edit-extend-typical-form`.
5. **Общая форма** — создай именно метаданные `CommonForm` (не общий модуль) через `/meta-compile`; этот инструмент формирует заготовку формы, которую наполняют через `/form-compile`.

## Рабочий порядок

- Уточни целевой объект, назначение формы и её тип (управляемая/иная), если они не заданы. Не подменяй форму новым объектом метаданных без необходимости.
- Перед компиляцией изучи `/form-patterns`; при наличии XML-схемы проекта используй её конвенции и установленные версии формата.
- Для формы с описанной структурой используй `/form-compile`; для простой пустой формы сначала `/form-add`. Не редактируй XML вручную, если инструменты покрывают требование.
- Проверь результат через `/form-info` и `/form-validate`; затем запусти валидатор соответствующего объекта/артефакта (`/meta-validate`, `/epf-validate`, `/erf-validate` или `/cfe-validate`).
- Если после создания требуется точечная правка существующего `Form.xml`, прочитай `../form-edit/references/form-edit-operations.md`; эта справка содержит только общий механизм структурных изменений.

## Граница

Не используй этот маршрут для изменения типовой формы или выбора способа расширения. Для формы, уже существующей в типовой конфигурации, сначала выбери механизм в `form-edit-extend-typical-form`; только там определяются динамические реквизиты, модульный перехват и заимствование.
