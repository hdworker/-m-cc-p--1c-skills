# Доработка типовой формы

Используй для формы поставщика в основной конфигурации или CFE. Сначала выбери механизм и подтверди фактическую цепочку вызова; затем меняй форму или модуль. Имя точки расширения само по себе не доказывает, что целевая форма через неё проходит.

## Сначала классифицируй изменение

- **Реквизит объекта** должен сохраняться в данных — добавь его в метаданные через `/meta-edit`. `ИзменитьРеквизиты()` не создаёт реквизиты объекта.
- **Динамический реквизит формы** нужен только интерфейсу — добавляй программно при создании формы; выбери подтверждённую точку исполнения ниже.
- **Структура формы** (элемент, группа, расположение, колонка) — меняй в Form.xml через форму расширения/заимствованную форму с помощью операций из `../form-edit/references/form-edit-operations.md`. `ИзменитьРеквизиты()` не заменяет изменение структуры.

## Модули переопределяемой модификации и контекст

Эти модули принимают перехватчики/переопределения процедур, относящихся к жизненному циклу форм и объектов. Код должен быть в модуле подходящего контекста; точный набор процедур, сигнатуру, директивы вызова и фактический путь вызова проверяй на целевом релизе.

| Модуль | Где выполняется | Когда рассматривать |
|---|---|---|
| `МодификацияКонфигурацииПереопределяемый` | Сервер | Серверные процедуры, например обработка формы в `ПриСозданииНаСервере` или `ПриЧтенииНаСервере`, если подтверждён вызов для нужной формы. |
| `МодификацияКонфигурацииВызовСервераПереопределяемый` | Сервер; процедура вызывается из клиентского кода | Серверную логику, для которой типовая цепочка инициируется клиентским вызовом. Это серверный, а не клиентский контекст. |
| `МодификацияКонфигурацииКлиентПереопределяемый` | Клиент | Клиентские события формы и процедуры; сюда относится, например, `ПослеЗаписи`, если фактическая сигнатура и точка вызова подтверждены. |
| `МодификацияКонфигурацииКлиентСерверПереопределяемый` | Клиент и сервер | Общие процедуры/перехватчики, допустимые и вызываемые в обоих контекстах; проверяй ограничения платформы и директивы компиляции. |

Перехватчики подключаются к вызову соответствующей процедуры формы: применимый вариант может выполняться до, после или вместо оригинала по поддерживаемому контракту точки расширения. Это не означает, что любой модуль может перехватить любое событие или что все события доступны как переопределяемые процедуры. Проверь имя, параметры, контекст и наличие точки вызова в исходниках текущей конфигурации.

## События формы

Событие — место жизненного цикла, где может требоваться логика; обработчик вставляй только в модуль, чей контекст соответствует исполнению события. Типовые примеры:

| Событие формы | Контекст | Что проверить |
|---|---|---|
| `ПриСозданииНаСервере` | Сервер | Нужная ли это форма, момент инициализации и сигнатура обработчика. Частый кандидат для программного добавления динамических реквизитов. |
| `ПриЧтенииНаСервере` | Сервер | Фактический порядок относительно создания формы и доступность данных на этой стадии. |
| `ПередЗаписьюНаСервере` | Сервер | Контракт параметров и допустимость изменения данных/отказа именно в выбранном перехватчике. |
| `ПослеЗаписиНаСервере` | Сервер | Выполняется ли действие до возврата клиенту и какие данные уже доступны. |
| `ПослеЗаписи` | Клиент | Клиентскую реализацию и фактическую связь с серверной записью; не подменяй этим серверный обработчик. |
| Другие события | По конкретному событию | Найди объявление/подключение обработчика, сигнатуру и вызывающий контекст в источниках этой версии. |

События формы могут быть точками перехвата через переопределяемые процедуры, но не полагайся только на совпадение названия процедуры. Для подключения и порядка (`&Перед`, `&После`, `&Вместо` или иной контракт) используй синтаксис и правила именно целевого механизма и релиза.

## Выбор механизма

| Вариант | Когда применять | Риск |
|---|---|---|
| **D. `МодификацияКонфигурацииПереопределяемый`** | Первый выбор для динамических реквизитов без заимствования, если целевая форма фактически проходит через `ПриСозданииНаСервере` этого модуля. | Низкий: не захватывает форму; проверь правило вендора и порядок обновлений. |
| **A. Модуль формы расширения** | Если D не вызывается/не подходит, а модуль формы расширения доступен для этой формы и нужного события. | Низкий: форма не заимствуется; проверь контекст и ограничения параметров. |
| **B. Заимствованная форма с декларативным изменением** | Только если нужную структуру нельзя выразить программно или механизм того требует. | Средний: возможен разрыв с типовой после обновления. |
| **C. Программное добавление в заимствованной форме** | Только если одновременно нужны структурное изменение и программная логика, которые нельзя разделить на менее инвазивные пути. | Средний/высокий: сочетает риск заимствования и код модуля формы. |

Для динамических реквизитов сначала проверяй D, затем A; B/C выбирай лишь с конкретным обоснованием. Для структурного изменения формы D/A не заменяют правку Form.xml.

## Ограничения динамических реквизитов

- Вызывай `ИзменитьРеквизиты()` только из `ПриСозданииНаСервере` или из переопределяемой процедуры, достоверно вызванной оттуда. Не переноси вызов в `ПриЧтенииНаСервере` или клиентский обработчик без подтверждённого требования платформы.
- Передавай список одним массивом за один вызов; защити инициализацию от повторного выполнения (например, маркером в `Параметры` с уникальным префиксом расширения).
- Не устанавливай напрямую `Отказ = Истина` в модуле формы расширения при `ПриСозданииНаСервере`: возможно «Запрещено изменение параметра, отменяющего действие». Для такого сценария используй только подтверждённый путь и допустимый контекст.
- Проверь путь данных каждого элемента, тип, видимость, доступ и права; тяжёлые значения (например, `ХранилищеЗначения`) не включай в запрос списков через `.*` без необходимости.

## Справки с примерами ERP

- При проверке обработчиков событий и цепочки вызовов открой `references/module-events.md`.
- При изучении передачи управления через переопределяемый модуль открой `references/overrideable-modules.md`.
- При сравнении централизованной библиотеки программных изменений форм открой `references/form-localization.md`.

## Проверки и выполнение

1. Зафиксируй целевую конфигурацию, релиз, платформу, форму, контекст и ограничения поддержки. Исследуй именно эти исходники.
2. Найди фактическую цепочку вызовов, сигнатуру, условия и порядок для выбранного события. Если исходников нет — укажи «не проверено», а не «механизма нет».
3. Сначала изучи форму через `/form-info`; для сохраняемого реквизита используй `/meta-edit`. Для структуры подготовь JSON и примени операции из общей справки `../form-edit/references/form-edit-operations.md`.
4. `/cfe-borrow` применяй только после доказательства, что D/A не покрывают требование; заимствуй минимальный объём и зафиксируй риск расхождения с будущим релизом.
5. Для CFE проверь совместимость с основной конфигурацией и контролируемые свойства. Проверь результат `/form-validate` и, если применимо, `/cfe-validate`; runtime-поведение проверяй на целевой конфигурации и платформе.
6. В результате укажи выбранный механизм, подтверждённую цепочку и контекст события, ближайшую отвергнутую альтернативу, остаточную неопределённость и статус реквизитов `OK / риск / ошибка` с причиной.
